# DTOMapper Integration Architecture

**Status:** ✅ Production (v3.0.0+)
**Last Updated:** October 31, 2025
**Implementation:** `BooksTrackerPackage/Sources/BooksTrackerFeature/Services/DTOMapper.swift`

---

## Context

**Core Challenge:**
The iOS application receives canonical DTOs (`WorkDTO`, `EditionDTO`, `AuthorDTO`) from the backend `/v1/*` endpoints but needs to convert them to SwiftData models (`Work`, `Edition`, `Author`) for local persistence. Previously, this conversion logic was duplicated across search, enrichment, and scanning services, leading to inconsistencies.

**Specific Issues:**
1. **Duplicated Conversion Logic:** Multiple services implemented ad-hoc DTO → model conversion.
2. **Synthetic Work Deduplication:** Google Books often returns multiple "synthetic" works for the same book (e.g., 5 editions of "The Great Gatsby"). These need to be merged into a single `Work` entity with multiple `Edition`s.
3. **SwiftData Lifecycle:** SwiftData requires `modelContext.insert()` *before* setting relationships to avoid crashes involving temporary identifiers.
4. **Genre Normalization:** The backend normalizes genres; the iOS client must preserve these without re-normalizing.

---

## Solution Overview

The `DTOMapper` is a centralized service that converts canonical DTOs to SwiftData models. It enforces:
1. **Insert-Before-Relate Pattern:** Ensures stability by inserting objects into the context before establishing relationships.
2. **Synthetic Work Deduplication:** Automatically groups synthetic works by ISBN to create a clean library view.
3. **Genre Preservation:** Directly maps normalized tags from the DTO.

---

## Functional Requirements

### 1. Centralized Conversion
All services (`BookSearchAPIService`, `EnrichmentService`, `BookshelfScannerService`) must use `DTOMapper.mapToWorks()` to ensure consistent data ingestion.

### 2. Synthetic Work Deduplication
If multiple synthetic works share the same ISBN (common with Google Books results), they must be merged into a single `Work` entity containing all relevant `Edition`s.

### 3. Genre Consistency
Subject tags provided by the backend must be applied directly to the `Work` model, treating the backend as the source of truth for normalization.

## Technical Implementation

**Core Method: `mapToWorks`**

```swift
func mapToWorks(data: SearchResponseData, modelContext: ModelContext) -> [Work] {
    var works: [Work] = []

    for workDTO in data.works {
        // 1. Create Work model
        let work = Work(title: workDTO.title, ...)
        modelContext.insert(work) // CRITICAL: Insert BEFORE relating

        // 2. Apply genre normalization (backend source of truth)
        work.subjectTags = workDTO.subjectTags

        // 3. Create Author models
        let authors = insertAuthors(data.authors, modelContext)
        work.authors = authors // Safe - both have permanent IDs (or strictly managed temp IDs)

        // 4. Create Edition models
        let editions = insertEditions(data.editions, modelContext, work)
        work.editions = editions

        works.append(work)
    }

    // 5. Deduplicate synthetic works
    return deduplicateSyntheticWorks(works, data.editions)
}
```

**Deduplication Logic**

```swift
private func deduplicateSyntheticWorks(_ works: [Work], _ editions: [EditionDTO]) -> [Work] {
    let syntheticWorks = works.filter { $0.synthetic == true }
    let grouped = Dictionary(grouping: syntheticWorks, by: { work in
        // Group by ISBN (from editions)
        editions.first { $0.workId == work.id }?.isbn ?? ""
    })

    var deduplicated: [Work] = []
    for (isbn, duplicateWorks) in grouped where duplicateWorks.count > 1 {
        // Merge editions into first work, delete rest
        let primaryWork = duplicateWorks[0]
        for work in duplicateWorks.dropFirst() {
            primaryWork.editions.append(contentsOf: work.editions)
            modelContext.delete(work)
        }
        deduplicated.append(primaryWork)
    }

    return works.filter { $0.synthetic == false } + deduplicated
}
```

## Architecture Decision Log

### [October 29, 2025] Decision: Single DTOMapper Service
**Rationale:** Centralize conversion logic to facilitate testing and enforce the critical insert-before-relate pattern for SwiftData stability.

### [October 29, 2025] Decision: Deduplicate by ISBN
**Rationale:** ISBN is the most reliable unique identifier for editions and effectively handles synthetic works generated by providers like Google Books.

### [October 29, 2025] Decision: Backend Genre Normalization
**Rationale:** The backend performs complex normalization (e.g., mapping "Science Fiction" and "Sci-Fi" to "Science Fiction"). The iOS client treats the backend response as the single source of truth.

## Future Considerations

- **Provenance Tracking:** Consider storing `primaryProvider` in SwiftData models for debugging.
- **Fuzzy Deduplication:** Potential future need to handle typos in titles (e.g., "The Great Gatbsy").
- **Conflict Resolution:** UI for manual resolution of duplicate works if automatic merging fails.
